03 / DETECT
Check stored events
Runs only when you choose

      
Evaluate the complete stored dataset and save the results. Repeated checks add a run without duplicating unchanged alerts.

      

      
Importing does not run this check automatically. Checking unchanged records again adds a run without duplicating their alerts.

      
What do R1, R2, and R3 check?
  • R1: at least 5 failed logins for the same account and IP within 5 minutes.
  • R2: failures across at least 10 different accounts from one IP within 10 minutes.
  • R3: a successful login after at least 5 earlier failures for the same account and IP within 5 minutes. Failures at the exact success time do not count.
Choose All rules for the complete check. This prototype checks up to 10,000 events and 100,000 supporting references. If a limit is exceeded, the run is not partly saved.

      
How do I read the result?
New: findings saved for the first time. Already saved: matching findings recorded earlier. Total: all unique saved alerts.
Example: the first check finds 3 new alerts. Checking the same records again finds 0 new and 3 already saved. That means duplicate prevention worked. You now have 3 alerts and 2 runs.
Roman Urdu: Zero new ka matlab check fail hona nahi. Wohi alerts pehle se save hon to unki duplicate copy nahi banti.

05 / HISTORY
Detection runs
Newest run first

      
One row per completed check. Open a run's alerts to see the findings from that particular check, including alerts saved earlier.
Understand the history columns and times
Events: records checked. Matched: findings from that check. New + Existing = Matched. A completed check may find zero alerts.
All displayed times are UTC. Pakistan time is UTC plus 5 hours: 09:00 UTC is 14:00 in Pakistan. Trigger time is when the suspicious pattern happened; completed time is when you checked it.
Refresh history reloads the lists without running detection. Viewing evidence never creates a run.

Status, conclusion, and revision explained
Status tells you where the work has reached. Conclusion records your judgment. Confirmed compromise needs supporting investigation, not just an alert. A closed case may still have a suspicious conclusion; closed does not mean safe.
Revision increases with every saved action. If another action changed the case, refresh and review the latest history before saving your decision again. Your reason stays in the box; the selectors reset to the latest saved values.
